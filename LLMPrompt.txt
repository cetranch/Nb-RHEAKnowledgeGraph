# ONTOLOGY

## Node labels (classes)
- Paper: the source publication. REQUIRED property: doi
- Alloy: a metallic substance composed of two or more elements
- Element: a chemical element (e.g., Nb, Cr)
- Specimen: a sample of material prepared for testing
- OxidationTest: a test measuring oxidation behavior under specific conditions
- Oxide: a compound formed by reaction of an element with oxygen
- Property: a characteristic or quality of a material
- Phase: a distinct state of matter or crystallographic phase within a system
- Composition: the makeup of an alloy in terms of constituent elements and proportions
- Temperature: a measure of thermal energy (°C or K)
- Atmosphere: the gaseous environment surrounding a specimen during testing
- Kinetics: the rate and mechanism of oxidation processes

# USING LABELS TO EXTRACT DETAIL
Use each node label as a guide to what detail to capture, and store that detail as properties on the node. Do not create extra nodes for detail that fits as a property. Examples:
- Alloy: name/designation (e.g., "Nb-Si-Cr alloy"), nominal composition string, processing route (arc-melted, heat-treated)
- Element: symbol, name
- Composition: raw composition string, unit ("at.%", "wt.%"), and an `elements` map such as {"Nb": 45, "Cr": 5}
- Specimen: specimen ID/label, dimensions, surface finish, preparation method
- OxidationTest: test type (isothermal, cyclic, TGA), duration, number of cycles, heating/cooling rates, mass gain per area, scale thickness
- Oxide: formula (e.g., Nb2O5, CrNbO4), morphology, layer position (outer/inner), thickness, characterization method (XRD, SEM, EDS)
- Property: name, value, unit, measurement method (e.g., hardness, density, mass gain)
- Phase: name, crystal structure, space group, volume fraction
- Temperature: value, unit, and whether it is a test, melting, or heat-treatment temperature
- Atmosphere: composition (air, Ar, O2, steam), pressure, flow rate
- Kinetics: rate law (parabolic, linear, logarithmic, paralinear), rate constant with units, activation energy, regime/temperature range

If the paper gives a value with units, keep the value and unit as separate properties (e.g., "value": 1100, "unit": "°C"). Preserve numbers exactly as written. Also record `source_text`, a short verbatim snippet (max 25 words) supporting each node or relationship where practical.

# EXTRACTION RULES
1. Entity resolution: create one node per distinct real-world entity. Reuse the same node id when the paper refers to it multiple times (e.g., one "Temperature 1100 °C" node shared by every test at 1100 °C; one Element node per element).
2. IDs: use stable, readable IDs, e.g., "alloy_NbSiCr_1", "elem_Nb", "spec_A1", "test_A1_1100C_air", "temp_1100C", "atm_air".
3. Each Specimen should link to its Alloy (is_composed_of) and each OxidationTest to its Specimen (exhibits_oxidation_behavior). Each OxidationTest should have at_temperature and in_atmosphere links where stated.
4. If a Specimen's identity is ambiguous (the paper discusses an alloy generically), create the Alloy and an OxidationTest, and create a Specimen only if the paper describes an actual sample.
5. Only create relationships whose source and target labels match the table above.
6. If information is missing, omit the property or node. Do not use "unknown", "N/A", or guesses.
7. Capture results from tables and figure captions as well as prose. Do not extract data from referenced prior work unless the paper restates it as part of its own findings. If you must include it, set "from_cited_work": true on the node.
8. Use Neo4j-safe property types only: string, number, boolean, or arrays of these. No nested objects. Flatten maps such as the elements map into a JSON string or separate properties (e.g., "Nb_at_pct": 45).
9. Use the exact label and relationship names above (case-sensitive).
