# ONTOLOGY

## Node labels (classes)
- Paper: the source publication. REQUIRED property: doi
- AlloySeries: a general alloy family written as a formula with variables (e.g., AxBy)
- Alloy: a specific alloy with a defined composition (e.g., A3B2)
- Specimen: an alloy that has had a process done to it (a physical sample in a specific processed state)
- Process: the conditions a specimen was under (e.g., heat treatment, casting, annealing, deformation)
- Phase: a phase that an alloy or specimen has
- Feature: a microstructural feature (e.g., precipitate, grain boundary, dislocation, void)
- Element: a specific chemical element (e.g., Nb, Cr)
- Measurement: a measurement made on a specimen
- Mechanism: an explanation or rule model offered for an observed behavior
- Property: a general property of a material (e.g., hardness, yield strength, density)

# USING LABELS TO EXTRACT DETAIL
Use each node label as a guide to what detail to capture, and store that detail as properties on the node. Do not create extra nodes for detail that fits as a property. Required/expected properties per label:
- AlloySeries: formula (e.g., "AxBy")
- Alloy: composition (the composition string as written, e.g., "A3B2" or "Nb-45Ti-5Cr"); optionally unit ("at.%", "wt.%") and per-element amounts as separate flat properties (e.g., "Nb_at_pct": 45)
- Specimen: specimen ID/label, plus any preparation or dimension details the paper gives
- Process: process_name (e.g., "annealing", "arc melting", "aging"), temperature, pressure, time (each with a separate unit property, e.g., "temperature": 1100, "temperature_unit": "°C")
- Phase: name, volume_fraction (with unit), coherency (e.g., "coherent", "semi-coherent", "incoherent")
- Feature: name, size (with unit), composition
- Element: name (and symbol if given)
- Measurement: settings (instrument/technique and parameters, e.g., "XRD, Cu Kα, 40 kV"), temperature, time (with units). If the paper reports a measured value, store it as "value" and "unit" on the Measurement node.
- Mechanism: name, expression (the explanation, rule, or equation as stated in the paper)
- Property: name, temperature, pressure (the conditions the property applies under, with units)

If the paper gives a value with units, keep the value and unit as separate properties (e.g., "temperature": 1100, "temperature_unit": "°C"). Preserve numbers exactly as written. Also record `source_text`, a short verbatim snippet (max 25 words) supporting each node or relationship where practical.

Element role: an element's role (e.g., "solid-solution strengthener", "grain refiner") depends on the alloy, so store it as a `role` property on the has_component relationship, not on the shared Element node. Only record it if the paper states it.

# EXTRACTION RULES
1. Entity resolution: create one node per distinct real-world entity. Reuse the same node id when the paper refers to it multiple times (e.g., one Element node per element; one Process node shared by every specimen that underwent the identical process; one Property node per property under the same conditions).
2. IDs: use stable, readable IDs, e.g., "series_AxBy", "alloy_A3B2", "elem_Nb", "spec_A3B2_aged", "proc_anneal_1100C_2h", "phase_gamma_prime", "feat_precipitate_1", "meas_XRD_1", "mech_orowan", "prop_hardness".
3. Structure: an Alloy links to its Specimens (has_specimen); each Specimen links to its Process(es), Phase(s), Feature(s), and Measurement(s). If the paper names a general formula or family, create an AlloySeries and link it to each Alloy it covers (has_alloy).
4. Multi-step processing: if a specimen goes through several steps, create one Process node per step and add an `order` property (1, 2, 3...) to each underwent_process relationship.
5. Measurements and properties: link each Measurement to the Property it determines (measures_property). Link a Specimen directly to a Property (has_property) when the paper states the property of that specimen. Put the measured value on the Measurement node when a measurement is described, otherwise on the Property node.
6. Mechanisms: create a Mechanism node only when the paper offers an explanation, model, or rule. Link it to what it explains (explains). Do not create a Mechanism for plain descriptions of results.
7. If a Specimen's identity is ambiguous (the paper discusses an alloy generically), create the Alloy and attach Phases, Features, Properties, and Measurements to the Specimen only if the paper describes an actual processed sample. Otherwise attach Process, Phase, Feature, and Property information using the closest valid relationship in the table and add a warning.
8. Only create relationships whose source and target labels match the table above.
9. If information is missing, omit the property or node. Do not use "unknown", "N/A", or guesses.
10. Capture results from tables and figure captions as well as prose. Do not extract data from referenced prior work unless the paper restates it as part of its own findings. If you must include it, set "from_cited_work": true on the node.
11. Use Neo4j-safe property types only: string, number, boolean, or arrays of these. No nested objects. Flatten maps into separate properties (e.g., "Nb_at_pct": 45) or a JSON string.
12. Use the exact label and relationship names above (case-sensitive).
